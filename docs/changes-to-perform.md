I need to perform a simplification to the substrate. I don't need Entity-components. Entity-attributes are ok, as long as an attribute can be a list (for example person.telephonnumber is a list attribute, not a scalar attribute).

Also my idea (but maybe it was already in the last version of the plan - please check - is that rules are homoiconic i.e. they are described by entities and attributes; also the "training" process grows "scoring rules" that score the applications of rules. The training process might grow a "stygmergic" control network made of attribute-setting rules, where these "control" attributes might be opaque identifiers, so that the trajectory is altered in multiple steps: a rule might change an attribute, and this steers the trajectory a bit, then another application of scoring rules makes another change, and so on. This allows some scoring rules to be "shared" in terms of trajectory altering, similar to what happens in a decision trees, where upper levels cut out branches of the tree ). We will need to identify a suitable algorithm, either EA, or other algorithms, to "grow" this control network.

Also I am thinking, we could create a set of "knowledge maze" problems to train the system, where the correct answer is only find by applying a set of rules whose application has not been coded, but rather guided by the "control network"
